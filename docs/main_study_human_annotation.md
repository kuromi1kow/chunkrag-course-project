# TechQA human-annotation protocol

Implements Immutable Specification Section 22 and E4. Annotators receive only the
blinded package generated by the E4 `human-package` work item.

## Dimensions

Correctness:

- 0: incorrect or contradicts the reference resolution;
- 1: partly correct but contains a substantive error or ambiguity;
- 2: fully correct.

Completeness:

- 0: misses the resolution;
- 1: contains part of the information needed to resolve the question;
- 2: contains the information needed to resolve the question.

Groundedness, annotated only when context is displayed:

- 0: contains a major unsupported claim;
- 1: contains a minor unsupported or unverifiable detail;
- 2: fully supported by the consumed context.

Use `cannot_assess` only when the public question/reference/context makes a principled
score impossible, and provide a reason. Do not infer the system identity. Do not use
automatic scores or outside tools.

Both annotators complete the identical 20-record training package from TechQA questions
ranked 61 onward. These records are excluded. Every disagreement and `cannot_assess`
record is adjudicated jointly to an integer consensus in {0,1,2}; unresolved records
remain `cannot_assess`.

## Label files

Two independent files and one adjudicated file use canonical JSONL with fields:

```json
{"annotation_record_id":"...","correctness":2,"completeness":1,"groundedness":null,"cannot_assess_reason":null}
```

Store them as:

- `evaluation/human/human-labels-a.jsonl`
- `evaluation/human/human-labels-b.jsonl`
- `evaluation/human/human-adjudicated.jsonl`

The E4 `human-validation` work item validates all 360 IDs, computes agreement, applies
the judge thresholds mechanically, and writes `judge-validation.json`.

Each annotator is budgeted 17 hours and receives USD 25/hour or the higher institutional
minimum. Consent and contact information are stored separately and are never released.
